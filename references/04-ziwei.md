# 04 · 紫微斗数

## 一、来源性质

托名宋·陈抟的《紫微斗数全书》为现存最主要文本，另有《紫微斗数全集》（明）及《太微赋》《骨髓赋》等赋文。学界对实际成书年代有争议（明代说与清代说并存），且**《四库全书》术数类未收紫微斗数**。

结论：紫微斗数是**民间体系**，与子平命理同属"命书相书"的实务范畴，但其典籍序列的权威性不如《三命通会》《子平真诠》。引用时应说"《紫微斗数全书》云"，不要说"古法"。

## 二、与八字的根本差异

| | 八字 | 紫微斗数 |
|---|---|---|
| 基本单位 | 干支的五行生克 | **星曜落在哪一宫** |
| 论命方式 | 格局、旺衰、十神 | 星曜组合、宫位关系、四化 |
| 强项 | 一生层次、大势起伏 | **十二个生活领域的分布**——哪个领域强、哪个弱 |
| 时间粒度 | 大运流年 | 大限（十年）＋流年＋小限 |

两者**互不推导**。八字好不等于紫微命宫强，两者是不同模型的投影。用户同时问时，分别陈述、不给加权平均。

## 三、十二宫

| 宫位 | 主管 |
|---|---|
| 命宫 | 性格底色、先天禀赋、一生总纲 |
| 兄弟 | 手足、同侪、合作方 |
| 夫妻 | 婚姻、配偶特质、亲密关系模式 |
| 子女 | 子女、下属、创作产出 |
| 财帛 | 求财方式、金钱观 |
| 疾厄 | 体质倾向（**不作疾病诊断**） |
| 迁移 | 外出、环境变动、对外形象 |
| 交友（仆役） | 朋友、部属、人脉 |
| 官禄（事业） | 事业形态、职业倾向 |
| 田宅 | 不动产、家庭环境、根基 |
| 福德 | 精神生活、兴趣、寿元相关（**不谈寿元**） |
| 父母 | 长辈、上级、庇荫 |

**身宫**落于何宫，表示该领域是一生着力处。

## 四、十四主星与四化

**紫微系（北斗）**：紫微、天机、太阳、武曲、天同、廉贞
**天府系（南斗）**：天府、太阴、贪狼、巨门、天相、天梁、七杀、破军

**四化**由生年干决定，流年干另起一轮：

| 四化 | 性质 |
|---|---|
| 化禄 | 增益、财源、顺利的方向 |
| 化权 | 掌控、权力、主动作为 |
| 化科 | 名声、文书、贵人 |
| 化忌 | 阻碍、牵绊、需要偿还的地方 |

化忌所落之宫，是**一生态度最用力、也最容易吃力不讨好的领域**。这是紫微最实用的单点判据之一。

## 五、两大流派

| | 三合派 | 飞星四化派 |
|---|---|---|
| 入手 | **命宫的三方四正**（本宫＋三合两宫＋对宫） | **宫位之间的四化飞渡** |
| 核心问题 | 这组星曜组合好不好、成什么格 | 哪个宫把四化飞给了哪个宫，谁欠谁 |
| 代表传承 | 中州派（王亭之）、紫云派 | 钦天门、河洛派 |
| 强项 | 性格与格局的描述力 | 具体事件与人际动态的推断 |
| 弱项 | 对具体事件的时间定位弱 | 缺乏格局层面的整体把握 |

**本 skill 默认三合派**（引擎 iztro 的默认口径亦为南派三合体系）。若用户或某报告采用飞星派，须在解读前声明，因为两派对同一张盘的结论会不同。

## 六、判读顺序（三合派）

1. **看命宫主星及其庙旺落陷** → 定性格底色与基本格局。
2. **取三方四正** → 看命宫的支援与牵制来自哪里。
3. **看四化落宫** → 找出"最用力"与"最得利"的领域。
4. **看身宫** → 一生着力点。
5. **过十二宫** → 按用户所问的领域细看该宫星曜。
6. **走大限流年** → 用 `ziwei.js` 输出的「大运一览」与「流年」段落定位当前阶段。

## 七、常见格局（举例，非穷举）

| 格局 | 星曜条件 | 传统判语 |
|---|---|---|
| 紫府同宫 | 紫微、天府同守命宫 | 稳重有守，格局端方 |
| 紫府朝垣 | 紫微天府夹拱命宫 | 得贵助 |
| 杀破狼 | 七杀、破军、贪狼三方会照 | 变动大、开创型，宜动不宜守 |
| 机月同梁 | 天机、太阴、天同、天梁会照 | 宜公职、幕僚、专业技术 |
| 日月同宫／并明 | 太阳太阴同宫或分守 | 阴阳并济，主见识与局面 |
| 君臣庆会 | 紫微与左右魁钺昌曲同宫 | 得人相助 |
| 三奇加会 | 化禄化权化科三方会齐 | 顺遂有力 |

格局匹配**只是入口**，不可就此收口。必须落到三方四正的实际组合与四化落宫。

## 八、引擎能力边界

**用法**（engine 层脚本无 `--out`，须经桥接层捕获，否则中文乱码）：

```powershell
Set-Location $SKILL_ROOT\scripts
& $NODE run-engine.cjs ziwei.js 2000-05-15 男 未 --out "$env:TEMP\ziwei.txt"
```

时辰可传单字（子／丑／…／亥）或 `HH:MM`；性别传「男」「女」。

**已实测缺陷 1 · 交节日的八字月柱错误（含下游污染）**

`ziwei.js` 会在盘首附带打印一行「八字：……」，该行**不可直接采信**——它按「日期」判月柱，不按节气交接时刻。实测三例：

| 日期 | 传入时刻 | cantian 八字 | ziwei 打印的八字 | 结论 |
|---|---|---|---|---|
| 2000-05-05（立夏当天，cantian 实测翻转点在 **12:00–13:00** 之间） | 06:00 | 庚辰 **庚辰** 癸亥 乙卯 | 庚辰 **辛巳** 癸亥 乙卯 | 月柱错 |
| 2000-06-05（芒种当天，实测翻转点在 **16:00–18:00** 之间） | 06:00 | 庚辰 **辛巳** 甲午 丁卯 | 庚辰 **壬午** 甲午 丁卯 | 月柱错 |
| 2000-06-10（非交节日） | 06:00 | 庚辰 **壬午** 己亥 丁卯 | 庚辰 **壬午** 己亥 丁卯 | 一致 ✓ |

复算方式（两侧传同一钟表时刻）：cantian 侧 `node run-cantian.cjs buildBaziFromSolar.ts 2000-05-05T06:00:00 1 2 --out out.md`；ziwei 侧 `node run-engine.cjs ziwei.js 2000-05-05 男 06:00 --out out.txt`。表中「cantian 八字」列按真太阳时口径输入。

规律：**交节日全天月柱提前一位；非交节日与 cantian 完全一致**（日柱、时柱在所有样本中均正确）。

**下游污染范围（2026-09-11 实测补全）**——错误月柱不止影响那一行，它会连带污染三块判读：

| 层级 | 2000-05-05 立夏当天实测 |
|---|---|
| 月柱 | ziwei 报 **辛巳** ❌ ／ cantian 报 **庚辰** ✅ |
| 月令 | ziwei 据此推「**巳月**」❌（实为辰月） |
| 格局 | ziwei 据此推「**偏财格**」❌ ／ `bazi-analysis.js` 报「**正官格**（善用神 ❌ 否——用神有害）」✅ |
| 扶抑取用 | ziwei 报「中和 **292 分**，宜补木、水，宜避火」；真实辰月盘 `bazi-analysis.js` 判偏弱 **165 分**，取印比生扶 |

→ 引用 ziwei 输出时**必须屏蔽其「八字」「月令」「格局」「用神」四块**。

**已实测缺陷 2 · 内置八字强弱算法与专责模块口径冲突（2026-09-11 新发现）**

`ziwei.js` 内部另有一套八字强弱/用神算法，与 `bazi-analysis.js` **不同源**，结果可以完全对立：

| 命例 | `bazi-analysis.js` | `ziwei.js` 内置模块 | 是否冲突 |
|---|---|---|---|
| 甲木日主（2000-06-05 06:00） | 弱 **106 分**，宜取印比生扶（水木） | 偏强 **316 分**，宜补土，宜避木火 | **方向相反** |
| 癸水日主（2000-05-05 06:00） | 偏弱 **165 分**，宜取印比生扶 | 中和 **292 分**，宜补木、水 | 方向一致，差 127 分 |

→ **强弱分与用神一律只引 `bazi-analysis.js`**，永不在结论里引用 ziwei 输出的「综合 N 分」与「八字用神（增强算法）」两块。

处置：
1. **紫微盘体本身不受影响**——命宫以农历月定，与节气月无关，十二宫、主星、四化、大限照常使用。
2. **月柱一律以 cantian 为准**；引用八字时不要把 ziwei 那一行抄进结论。
3. **强弱分与用神只引 `bazi-analysis.js`**；ziwei 的「日主分析」「八字用神（增强算法）」「用神喜忌」三块一律丢弃。
4. 需要确认某日是否交节、交节在几点，用 `run-cantian.cjs buildBaziFromSolar.ts` 逐时刻扫月柱翻转点（`jieqi.js` 只给日期、不给时刻）。

## 九、自检问题

1. 我声明了用的是三合派还是飞星派吗？
2. 命宫的三方四正是哪几个宫？支援与牵制各来自哪里？
3. 化忌落在哪个宫？该宫主管的领域我有没有如实指出问题？
4. 我是不是把紫微的结论和八字的结论混在一段里讲，让用户以为两者互相印证？
5. 疾厄宫、福德宫的内容有没有越界成疾病诊断或寿元判断？
6. 我引用的八字月柱来自哪里？（必须来自 cantian；ziwei 打印的那一行在交节日是错的）
7. 我引用的强弱分与用神来自哪个引擎？（必须来自 `bazi-analysis.js`；ziwei 的「日主分析」「八字用神（增强算法）」「用神喜忌」三块与它可能方向相反，一律丢弃）
8. ziwei 是否在交节日给出了「月令／格局」？若有，我有没有识别出这是错误月柱的下游产物？
